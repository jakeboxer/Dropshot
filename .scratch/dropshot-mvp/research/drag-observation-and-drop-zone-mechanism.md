# Drag observation and Drop Zone mechanism

## Decision

Use a native AppKit, permission-free hybrid:

1. Install matching global and local `NSEvent` monitors for left-mouse-dragged and left-mouse-up events. The global monitor observes events delivered to other apps, while the local monitor covers Dropshot; Apple explicitly says both are needed for complete app/non-app coverage. Global mouse monitoring is observational and Apple documents Accessibility trust only for **key-related** events, so this design must not monitor key-down, flags-changed, or Escape. [[Apple: `addGlobalMonitorForEvents`](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents%28matching%3Ahandler%3A%29)] [[Apple: Monitoring Events](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)]
2. On an observed drag event, inspect `NSPasteboard(name: .drag)`. Apple defines this named pasteboard as the pasteboard that stores drag data and says the drag pasteboard transfers data being dragged between apps. Treat exactly one readable HEIC file URL as an early Eligible Drag. Also recognize a single HEIC `NSFilePromiseReceiver` by its advertised `fileTypes`, but regard this as provisional until the Drop Zone receives the drag. [[Apple: `NSPasteboard.Name.drag`](https://developer.apple.com/documentation/appkit/nspasteboard/name-swift.struct/drag)] [[Apple: `NSPasteboard`](https://developer.apple.com/documentation/appkit/nspasteboard)] [[Apple: `NSFilePromiseReceiver`](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver)]
3. Show a reusable, borderless, nonactivating `NSPanel` whose content view registers for `.fileURL` and every type in `NSFilePromiseReceiver.readableDraggedTypes`. Do not activate Dropshot or make the panel key. Apple documents that `.nonactivatingPanel` does not activate its owner, and that a destination gets `draggingEntered` only after the pointer enters a registered view/window; therefore destination callbacks alone cannot make the zone appear at drag start. [[Apple: `nonactivatingPanel`](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)] [[Apple: `draggingEntered`](https://developer.apple.com/documentation/appkit/nsdraggingdestination/draggingentered%28_%3A%29)] [[Apple: `readableDraggedTypes`](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver/readabledraggedtypes)]
4. Once the pointer enters the panel, use `NSDraggingInfo.draggingPasteboard` as the authoritative payload and reject unless it resolves to exactly one HEIC input. On drop, prefer a file promise over a URL when both exist, because Apple's sample says promises generally represent the higher-quality image. Fulfill a promise asynchronously into an app-controlled temporary directory; for a file URL, consume the URL granted by the drag. [[Apple: `draggingPasteboard`](https://developer.apple.com/documentation/appkit/nsdragginginfo/draggingpasteboard)] [[Apple: Supporting table-view drag and drop through file promises](https://developer.apple.com/documentation/AppKit/supporting-table-view-drag-and-drop-through-file-promises)]

This is the only public-API route found that can both notice pointer dragging outside Dropshot and obtain semantic drag data without Accessibility permission. It is a composition of public APIs, but Apple does **not** explicitly guarantee that arbitrary third-party processes may reliably inspect the named drag pasteboard before becoming a destination. Consequently, early HEIC detection—especially Messages' representation—is a release-blocking compatibility experiment, not a fact established by the documentation.

## Eligibility details

- For URL items, read `NSURL` objects with the file-URL-only pasteboard reading option and require one item whose type is `UTType.heic` (using resource content type where available, with filename-extension inference only as a fallback). Apple defines `UTType.heic` as HEIC image data and describes UTTypes as the system mechanism for identifying transfer/storage formats. [[Apple: system-declared UTIs](https://developer.apple.com/documentation/uniformtypeidentifiers/system-declared-uniform-type-identifiers)] [[Apple: Uniform Type Identifiers](https://developer.apple.com/documentation/uniformtypeidentifiers/)]
- For promises, use `NSFilePromiseReceiver`, not legacy filename pasteboard types. A non-item-based source can promise several files in one receiver, so both receiver count and each receiver's `fileNames`/`fileTypes` must be checked before accepting the eventual result. [[Apple: `NSFilePromiseReceiver`](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver)]
- Register promises before URLs and deduplicate the two representations of the same logical drag instead of counting them as two files. Apple's sample explicitly demonstrates that one drag can offer promise and URL representations and says to prefer the promise. [[Apple: file-promise sample](https://developer.apple.com/documentation/AppKit/supporting-table-view-drag-and-drop-through-file-promises)]
- A promise is only a future file with an advertised type; its actual bytes arrive asynchronously at drop. The Drop Zone may show based on the advertised HEIC type, but conversion must wait for fulfillment and validate the received file again. [[Apple: Supporting drag and drop through file promises](https://developer.apple.com/documentation/appkit/supporting-drag-and-drop-through-file-promises)]

## Panel placement and window behavior

- Anchor to the current status item's actual button window (`statusItem.button?.window`) and convert its bounds to screen coordinates each time the zone is shown. Do not assume the primary screen: Apple distinguishes the primary screen from the screen containing the focused window, and display configuration can change dynamically. [[Apple: `NSStatusItem.button`](https://developer.apple.com/documentation/appkit/nsstatusitem/button)] [[Apple: `NSScreen.screens`](https://developer.apple.com/documentation/appkit/nsscreen/screens)]
- Position the panel immediately below that screen rect and clamp it to the current screen's `visibleFrame`; Apple defines `visibleFrame` as excluding the menu bar, Dock, and camera housing. [[Apple: `visibleFrame`](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)]
- Configure the panel with `.canJoinAllSpaces`, `.transient`, and `.fullScreenAuxiliary`, and use status/floating window level plus `orderFrontRegardless()` to appear above ordinary app windows without activation. Apple says `canJoinAllSpaces` makes a window appear in every Space, `fullScreenAuxiliary` places it on the full-screen window's Space, window levels determine stacking, and `orderFrontRegardless` can show a window in front even while another app is active. [[Apple: `NSWindow.CollectionBehavior`](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)] [[Apple: `fullScreenAuxiliary`](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary)] [[Apple: window levels](https://developer.apple.com/documentation/appkit/nswindow/level-swift.struct)] [[Apple: `orderFrontRegardless`](https://developer.apple.com/documentation/appkit/nswindow/orderfrontregardless%28%29)]
- Do not use an invisible screen-sized destination window. A window with `ignoresMouseEvents = true` is transparent to mouse events and cannot serve as a drop target; with it false, it risks intercepting interactions and drops intended for other apps. [[Apple: `ignoresMouseEvents`](https://developer.apple.com/documentation/appkit/nswindow/ignoresmouseevents)]
- Auto-hidden menu bars/full-screen modes remain a product constraint: if the status item's button window is unavailable or offscreen, do not guess an anchor. Suppress the zone for that drag or use a separately specified fallback. Apple exposes whether the menu bar is visible, but does not promise a usable status-item frame while it is hidden. [[Apple: `menuBarVisible`](https://developer.apple.com/documentation/appkit/nsmenu/menubarvisible%28%29)]

## Option override and drag termination

- Determine the Option override continuously from `NSEvent.modifierFlags` / `NSEvent.modifierFlags` class state or the modifier flags carried by each mouse-dragged event. Apple exposes `.option` and documents both per-event and current modifier state. This avoids globally monitoring keyboard events and therefore avoids the documented Accessibility requirement for key monitoring. [[Apple: modifier flags](https://developer.apple.com/documentation/appkit/nsevent/modifierflags-swift.property)] [[Apple: `ModifierFlags.option`](https://developer.apple.com/documentation/appkit/nsevent/modifierflags-swift.struct)]
- Hide on observed mouse-up (global or local), successful `performDragOperation`, or `draggingEnded`. Apple says `draggingEnded` notifies a destination even when the drag ends at another destination, which covers sessions that entered and then left the Drop Zone. [[Apple: `draggingEnded`](https://developer.apple.com/documentation/appkit/nsdraggingdestination/draggingended%28_%3A%29)]
- Also run a short-lived timer while visible and query `CGEventSource.buttonState(.combinedSessionState, button: .left)`; hide if the button is up. Apple documents this as the current button state for the user login session. This repairs missed mouse-up delivery but cannot detect Escape cancellation while the button remains held. [[Apple: `buttonState`](https://developer.apple.com/documentation/coregraphics/cgeventsource/buttonstate%28_%3Abutton%3A%29)] [[Apple: event-source state IDs](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid)]
- Prompt Escape dismissal without Accessibility permission is not guaranteed by the reviewed public APIs. A global key monitor would require Accessibility trust; requiring that permission is disproportionate for this MVP. Use a conservative inactivity/stale-drag timeout as a UI failsafe, and verify Escape behavior experimentally. [[Apple: `addGlobalMonitorForEvents`](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents%28matching%3Ahandler%3A%29)]

## Sandbox and permissions

- The event-monitor portion requires no Accessibility permission as long as its masks contain mouse events only. Do not use a Core Graphics keyboard event tap: Apple likewise conditions key-up/key-down event-tap delivery on assistive-device access. [[Apple: `CGEventTapCreate`](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate%28tap%3Aplace%3Aoptions%3Aeventsofinterest%3Acallback%3Auserinfo%3A%29)]
- App Sandbox can support the drop itself: Apple says dragging items to an app automatically expands its sandbox to include those items. Use URL representations, because Apple specifically warns that path strings do not cause sandbox expansion. [[Apple: Enabling App Sandbox](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html)] [[Apple: Dragging Files](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/DragandDrop/Tasks/DraggingFiles.html)]
- No persistent security-scoped bookmark is needed because Dropshot processes the file immediately and keeps no history. Promise fulfillment needs an app-controlled temporary destination and cleanup after conversion; this does not create a user-visible permanent file.

## Required compatibility spike before freezing the MVP spec

Build the smallest signed menu-bar probe for each targeted macOS major version and record the drag pasteboard types/items at (a) first global mouse-dragged event, (b) `draggingEntered`, and (c) `performDragOperation` for exactly these cases:

1. one HEIC attachment dragged from Messages;
2. one HEIC from Finder;
3. one non-HEIC from each;
4. two HEICs and a HEIC-plus-other mixed drag;
5. Option pressed/released during the drag;
6. cancellation by Escape, release outside the zone, and drop into another app;
7. separate-display Spaces, Stage Manager, and a full-screen app with menu bar shown and auto-hidden;
8. sandbox enabled and disabled.

Acceptance: Messages exposes enough public drag-pasteboard metadata before destination entry to distinguish one HEIC from ineligible drags, the panel becomes a functioning destination without activating Dropshot, file URL/promise access survives sandboxing, and every termination path removes the panel. If the first condition fails, the stated automatic **eligible-only** appearance cannot be implemented reliably with documented permission-free APIs; the product must choose between showing speculatively for all file drags, requesting Accessibility and investigating a key/event-tap approach (which still does not supply semantic drag data), or changing the interaction.

## Rejected alternatives

- `NSDraggingDestination` alone: definitive and supported for inspection/drop, but it fires only after the pointer enters an already-visible registered destination, too late to summon that destination. [[Apple: `draggingEntered`](https://developer.apple.com/documentation/appkit/nsdraggingdestination/draggingentered%28_%3A%29)]
- Accessibility APIs: they describe UI elements, not drag pasteboard semantics, and add an avoidable trust prompt.
- Core Graphics event taps: lower-level pointer observation offers no documented semantic drag payload advantage over `NSEvent`, while keyboard monitoring creates a permission burden. [[Apple: `CGEventTapCreate`](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate%28tap%3Aplace%3Aoptions%3Aeventsofinterest%3Acallback%3Auserinfo%3A%29)]
- Polling the general clipboard: Apple distinguishes the general pasteboard from the drag pasteboard, so ordinary clipboard changes do not identify current drags. [[Apple: `NSPasteboard`](https://developer.apple.com/documentation/appkit/nspasteboard)]

## Confidence

High for destination handling, file promises/URLs, panel Spaces behavior, mouse event monitoring, and permission boundaries because Apple documents those APIs directly. Medium for system-wide **early semantic detection** because the public pieces exist but Apple does not explicitly state the timing/visibility guarantee Dropshot needs. Low until tested for Messages' exact payload representation and menu-bar anchoring in auto-hidden/full-screen configurations.
